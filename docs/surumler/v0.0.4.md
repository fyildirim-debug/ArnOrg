ArnOrg runs Claude Code agents like a software company: you open a project and give a brief; the CEO agent writes the plan, hires the team, hands out the work and reports back to you. This release makes the company safer to leave running: approved work is tested before it reaches your branch, the team works within the limits you set, and agents pick up where they left off when ArnOrg restarts.

## New in 0.0.4

- **A quality gate for merges.** An approved merge no longer goes straight into your branch. It joins the project's merge queue (one merge at a time per project) and is tried first in a separate quality workspace:
  - ArnOrg merges the branch there and runs the project's setup and test commands. You set them in the project settings; ArnOrg suggests `npm test` when package.json has a real test script.
  - Only if the tests pass does the work reach your branch.
  - The approval card shows the live state: queued, testing, merged, tests failed, conflict or timed out. It also shows the test output and opens the diff.
  - When the tests fail, the agent gets the end of the output and fixes the work. You can also choose **Retry** or **Merge anyway**.
- **Merges are no longer auto-approved by default.** New projects leave merges to you; choices you already made stay as they are.
- **A team that works within your limits** (Settings → Work pattern):
  - At most 3 agents work at the same time (you can change it). The others wait their turn and start in order when a place frees up. Your own messages, and answers to a teammate's question, skip the queue.
  - Task token ceiling, 2 M processed tokens by default. When a task reaches it, the agent pauses and you're asked whether it should go on. If you approve, the ceiling grows by one step; if not, the agent's manager is asked to split the task.
  - A step limit for each turn, and a fallback model (Opus → Sonnet, Sonnet → Haiku) when the main model is overloaded.
  - **Stop work** now stops the whole project in one go, queue included.
- **Back to work after a restart.** Agents that were working when ArnOrg closed or crashed continue the same conversation about 30 seconds after it opens again. So do agents that were waiting in the queue, for the usage window or for a sign-in. Agents you stopped stay stopped.
- **Audit log:**
  - calls made by an agent's subagents are marked;
  - records older than the retention period (90 days by default) move to monthly JSONL archives in the data folder;
  - **Export** downloads the filtered log as JSONL.
- **Workspace cleanup.** When an agent leaves the team, its workspace is removed if it has no uncommitted changes; the branch and its commits stay. Stale worktree records are pruned.
- **Update bar** in the desktop app. When a new version has downloaded, a bar under the top bar offers **Restart**. ArnOrg checks for updates every 6 hours while it's open.
- **Fewer background checks.** Subscription usage is read only when it's needed: while Studio is open, while an agent is running, or while an agent waits for the usage window.

## Requirements

- **A Claude subscription** (Pro, Max or Team). ArnOrg only works with a subscription; it doesn't use API keys.
- The first-run assistant takes care of the Claude Code sign-in, git and the GitHub CLI. On Windows, Git for Windows is recommended.

## Good to know

- To turn on the quality gate, set a test command in each project's settings. Without one, merges are only checked for conflicts.
- The installers are unsigned. On the Windows SmartScreen prompt choose **More info → Run anyway**.
- The AppImage needs FUSE 2 (Ubuntu 24.04: `sudo apt install libfuse2t64`).
- Data: `%APPDATA%\ArnOrg` on Windows, `~/.config/ArnOrg` on Linux. Uninstalling doesn't remove user data. Upgrading from 0.0.3 keeps your projects, settings and sign-ins.

### 0.0.4'te yeni

- **Birleştirmeler için kalite kapısı.** Onaylanan birleştirme artık doğrudan dalınıza girmez. Projenin birleştirme kuyruğuna girer (proje başına aynı anda tek birleştirme) ve önce ayrı bir kalite çalışma alanında denenir:
  - ArnOrg dalı orada birleştirir, projenin hazırlık ve test komutlarını koşar. Komutları proje ayarlarında siz belirlersiniz; package.json'da gerçek bir test betiği varsa ArnOrg `npm test` önerir.
  - İş yalnız testler geçerse dalınıza girer.
  - Onay kartı canlı durumu gösterir: kuyrukta, testler çalışıyor, birleşti, testler geçmedi, çakışma ya da zaman aşımı. Test çıktısı da kartta görünür, fark oradan açılır.
  - Testler geçmezse ajan çıktının sonunu alır ve işi düzeltir. **Yeniden dene** ya da **Yine de birleştir** de seçebilirsiniz.
- **Birleştirmeler artık varsayılan olarak otomatik onaylanmaz.** Yeni projelerde birleştirme kararı sizde kalır; önceden yaptığınız seçimler olduğu gibi durur.
- **Koyduğunuz sınırlar içinde çalışan ekip** (Ayarlar → Çalışma düzeni):
  - Aynı anda en çok 3 ajan çalışır (değiştirebilirsiniz). Diğerleri sırasını bekler ve yer açıldıkça sırayla başlar. Sizin mesajlarınız ve bir ekip arkadaşının sorusuna verilen yanıt sırayı atlar.
  - Görev token tavanı, varsayılan 2 M işlenen token. Bir görev buna ulaşınca ajan durur ve size sürüp sürmeyeceği sorulur. Onaylarsanız tavan bir adım artar; onaylamazsanız ajanın yöneticisinden görevi bölmesi istenir.
  - Her tur için adım sınırı; ana model aşırı yüklüyse yedek model (Opus → Sonnet, Sonnet → Haiku).
  - **Mesaiyi durdur** artık sıra dahil bütün projeyi tek seferde durdurur.
- **Yeniden açılınca işe dönüş.** ArnOrg kapanırken ya da çökerken çalışan ajanlar, ArnOrg yeniden açıldıktan yaklaşık 30 saniye sonra aynı konuşmayla kaldıkları yerden sürer. Sırada, abonelik penceresini ya da girişi bekleyen ajanlar da sürer. Sizin durdurduğunuz ajanlar durmuş kalır.
- **Denetim kaydı:**
  - bir ajanın alt ajanlarının yaptığı çağrılar işaretlenir;
  - saklama süresinden (varsayılan 90 gün) eski kayıtlar veri klasöründeki aylık JSONL arşivlerine taşınır;
  - **Dışa aktar** süzülmüş kaydı JSONL olarak indirir.
- **Çalışma alanı temizliği.** Bir ajan ekipten ayrılınca, commit'lenmemiş değişikliği yoksa çalışma alanı kaldırılır; dal ve commit'leri kalır. Bayat worktree kayıtları budanır.
- **Güncelleme şeridi** (masaüstü uygulaması). Yeni sürüm indirilince üst çubuğun altındaki şerit **Yeniden başlat** önerir. ArnOrg açıkken 6 saatte bir güncellemeleri denetler.
- **Daha az arka plan denetimi.** Abonelik kullanımı yalnız gerektiğinde okunur: Stüdyo açıkken, bir ajan çalışırken ya da bir ajan kullanım penceresini beklerken.

### Gerekenler

- **Claude aboneliği** (Pro, Max ya da Team). ArnOrg yalnız abonelikle çalışır; API anahtarı kullanmaz.
- Claude Code girişini, git'i ve GitHub CLI'ı ilk açılış asistanı halleder. Windows'ta Git for Windows önerilir.

### Bilinmesi gerekenler

- Kalite kapısını açmak için her projenin ayarlarında bir test komutu belirleyin. Test komutu yoksa birleştirmelerde yalnız çakışma denetlenir.
- Kurulum dosyaları imzasızdır. Windows SmartScreen uyarısında **Ek bilgi → Yine de çalıştır** seçin.
- AppImage için FUSE 2 gerekir (Ubuntu 24.04: `sudo apt install libfuse2t64`).
- Veriler: Windows'ta `%APPDATA%\ArnOrg`, Linux'ta `~/.config/ArnOrg`. Kaldırma kullanıcı verisini silmez. 0.0.3'ten yükseltmede projeleriniz, ayarlarınız ve girişleriniz korunur.
